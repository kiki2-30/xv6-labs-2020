RISC-V汇编实验答案

1. 哪些寄存器保存函数的参数？例如，在main对printf的调用中，哪个寄存器保存13？

在RISC-V调用约定中，函数参数保存在以下寄存器中：
- a0: 第一个参数
- a1: 第二个参数  
- a2: 第三个参数
- a3: 第四个参数
- a4: 第五个参数
- a5: 第六个参数
- a6: 第七个参数
- a7: 第八个参数

在main对printf的调用中：
```assembly
printf("%d %d\n", f(8)+1, 13);
```

从汇编代码可以看到：
- a0: 保存格式字符串"%d %d\n"的地址
- a1: 保存f(8)+1的结果，即12
- a2: 保存13

因此，寄存器a2保存参数13。

2. main的汇编代码中对函数f的调用在哪里？对g的调用在哪里(提示：编译器可能会将函数内联）？

从汇编代码分析：

函数g的汇编代码：
```assembly
0000000000000000 <g>:
   6:	250d                	addiw	a0,a0,3    # return x+3;
   8:	6422                	ld	s0,8(sp)
   a:	0141                	addi	sp,sp,16
   c:	8082                	ret
```

函数f的汇编代码：
```assembly
000000000000000e <f>:
  14:	250d                	addiw	a0,a0,3    # return g(x); 被内联为 x+3
  16:	6422                	ld	s0,8(sp)
  18:	0141                	addi	sp,sp,16
  1a:	8082                	ret
```

main函数中的printf调用：
```assembly
000000000000001c <main>:
  24:	4635                	li	a2,13        # 加载13到a2
  26:	45b1                	li	a1,12        # 加载12到a1 (f(8)+1的结果)
  28:	00000517          	auipc	a0,0x0
  2c:	7b050513          	addi	a0,a0,1968 # 加载格式字符串地址到a0
  30:	00000097          	auipc	ra,0x0
  34:	600080e7          	jalr	1536(ra) # 630 <printf>
```

分析：
- 对函数f的调用：编译器将f(8)内联优化，直接计算f(8)+1=12，在地址0x26处加载到a1寄存器
- 对函数g的调用：编译器将g(x)内联优化，f函数直接返回x+3，没有显式的g函数调用

3. printf函数位于哪个地址？

从汇编代码可以看到：
```assembly
  30:	00000097          	auipc	ra,0x0
  34:	600080e7          	jalr	1536(ra) # 630 <printf>
```

printf函数的地址是0x630。

4. 在main中printf的jalr之后的寄存器ra中有什么值？

jalr指令执行后，ra寄存器包含printf函数的返回地址，即jalr指令的下一条指令地址。

从汇编代码看，jalr指令在地址0x34，所以ra寄存器中的值是0x38（下一条指令的地址）。

5. 运行以下代码的输出是什么？

```c
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, &i);
```

分析：
- 57616的十六进制表示：57616 = 0xe110
- 0x00646c72在小端存储中的字节序列：72 6c 64 00
- ASCII码：72='r', 6c='l', 64='d', 00='\0'

输出：He110 World

6. 如果RISC-V是大端存储，为了得到相同的输出，你会把i设置成什么？

在大端存储中，字节顺序相反：
- 要得到"rld\0"，需要字节序列：72 6c 64 00
- 大端存储中，0x726c6400会存储为：72 6c 64 00

所以i应该设置为0x726c6400。

57616不需要更改，因为它是数值，不受字节序影响。

7. 在下面的代码中，"y="之后将打印什么？为什么会发生这种情况？

```c
printf("x=%d y=%d", 3);
```

"y="之后会打印一个不确定的值（垃圾值）。

原因：
- printf期望两个%d参数，但只提供了一个参数3
- 第一个%d会正确打印3
- 第二个%d会从栈上读取一个未初始化的值，这个值是不确定的
- 这是因为printf使用va_list机制，当参数不足时，会读取栈上的随机数据
